### 2. Quit During Spelling Review Cannot Verify Successful Publication

Files: `crates/carta-app/src/application.rs:2344-2350,3122-3126` and
`crates/carta-gui/src/main.rs:534-543,738-753`.

Reproduced at the shared application layer with a synthetic Document, a
controlled spelling protocol double, and a real disposable local Git remote:

1. Create a Document containing `syntheticword`, with language `fr_FR`.
2. Configure and synchronize a disposable local bare remote.
3. Execute `Command::CheckDocumentSpelling` and leave its selector open.
4. Execute `Command::Quit`.
5. Run `stage_sync(app.archive.root().to_path_buf())` successfully.
6. Call `app.apply_background_sync(&stage)`.

Observed result: `SyncApply::Stale`, not `SyncApply::Unchanged`.

Quit saves/checkpoints and sets `app.quit`, but leaves the spelling selector
active. `apply_background_sync` rejects every non-Editing mode before inspecting
the staged publication. The GUI close handler cancels LEAP, not the spelling
selector; its final-publication handler retries Stale results and reports
`Push finale non verificato dopo 3 tentativi` after three attempts.

The shared-layer Stale result was executed and reproduced. The complete physical
GUI close/retry sequence was not exercised manually; the GUI consequence above
is traced from the production handler, not claimed as a manual observation.

### 3. Fenced Markdown Code Is Sent to the Spelling Backend

File: `crates/carta-app/src/spelling.rs:47-80`.

Synthetic input:

````markdown
```rust
syntheticcode
```

proseword
````

Actual words received by the controlled backend:

```text
["syntheticcode", "proseword"]
```

Expected: only `proseword`. The scanner's own documented contract says it skips
code. A fenced block's content is a CommonMark Text event, and the scanner does
not track CodeBlock context. Consequently code identifiers are exposed to
review and replacement. The existing `safe_markdown_ranges` test passes but
does not assert exclusion of a real multiline code block.

### 4. Italian Trailing Apostrophe Is Excluded from the Word

File: `crates/carta-app/src/spelling.rs:64-79`.

Synthetic input: `po'`.

Actual token: `po`, excluding the final apostrophe. The tokenizer retains an
apostrophe only when followed by another alphabetic character. Thus the backend
does not receive the complete Italian spelling, and a replacement operates on
the truncated range, leaving the apostrophe behind. This is a tokenizer result,
not a claim about suggestions from an installed Italian dictionary.

### 5. Decomposed Unicode Accent Is Excluded from the Source Range

File: `crates/carta-app/src/spelling.rs:64-79`.

Synthetic Rust input: `"cafe\u{301}"`.

Actual token: `cafe`, byte range `0..4` of a six-byte source. The combining acute
accent is left outside the spelling/replacement span. A replacement can attach
the original accent to the replacement's final character rather than replacing
the full word. The range is a valid UTF-8 slice, but it is not the complete
authored Unicode word. This case is not covered by `unicode_source_offsets`.

## Additional Synthetic Verification

An external temporary Rust harness called the published `carta-app` and
`carta-core` public APIs without modifying repository tests. It used the same
`pulldown-cmark` 0.13.4 version as the workspace lockfile. Its final execution
returned exit status 1: eight checks passed and four assertion checks failed.
The four failed checks correspond to findings 2-5 above. Finding 1 was checked
separately with Cargo.

The spelling protocol double was a temporary executable named `hunspell`,
prepended to PATH only inside the harness process after the missing-backend
check. It deliberately marked every input word as an error and supplied a
fixed UTF-8 replacement:

```bash
#!/bin/bash
printf '@(#) controlled synthetic protocol double\n'
while IFS= read -r word; do
    printf '& %s 1 0: École\n\n' "$word"
done
```

This double tests source tokenization, response mapping, and application actions.
It is NOT Hunspell, does not test dictionary quality, and does not prove real
Hunspell protocol compatibility or personal-word recognition.
